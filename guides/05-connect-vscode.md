# Подключить компьютер клиента к офису (VS Code) — шпаргалка для установки на встрече

> Для КОГО: для тебя (администратора), делаешь на встрече у клиента. Не для клиента.
> Что даёт: клиент видит и правит файлы офиса со своего компа (Mac/Windows), перетаскивает документы.
> Бот при этом остаётся на сервере — VS Code просто ещё одно окно к тем же файлам.
>
> ПОМЕТКИ ДОСТОВЕРНОСТИ:
> [✓ проверено 2026-07-07 руками на сервере] — прошёл сам, видел вывод.
> [док] — по официальной документации VS Code, руками до конца не доведено (упирается в живой вход под аккаунтом).

---

## Идея в двух словах
Файлы офиса лежат на сервере (там же, где бот). Ставим на сервер маленькую программу-туннель.
Она через интернет соединяет компьютер клиента с этими файлами. Никакие порты открывать не надо,
пароли/ключи клиенту не нужны — вход по аккаунту.

---

## ЧАСТЬ 1 — на сервере (делаешь ты, один раз при установке)

### Шаг 1. Поставить программу VS Code CLI на сервер [✓ проверено]
Одна команда (качает и кладёт программу `code`):
```
curl -Lk "https://code.visualstudio.com/sha/download?build=stable&os=cli-alpine-x64" -o /tmp/vscode_cli.tar.gz
tar -xzf /tmp/vscode_cli.tar.gz -C /tmp
install -m755 /tmp/code /usr/local/bin/code
```
Проверить, что встала: `code --version` (должна показать номер, напр. 1.127.0).

### Шаг 2. Завести отдельного пользователя «office» (не root) [✓ проверено]
Безопасность: клиент работает НЕ под root, чтобы при краже доступа не отдать весь сервер.
```
useradd -m -s /bin/bash office
```
Папку офиса дать этому пользователю (пример):
```
chown -R office:office /home/office/office
```
(в боевой установке — папка реального офиса; путь подставить свой)

### Шаг 3. Запустить туннель [✓ проверено — видел этот вывод]
От имени office, из папки офиса:
```
sudo -u office code tunnel --accept-server-license-terms --name office
```
На экране появится РОВНО это:
```
To grant access to the server, please log into https://github.com/login/device and use code XXXX-XXXX
```
(код вида `A11F-2105`, живёт ~15 минут)

### Шаг 4. Войти под аккаунтом клиента [✓ путь проверен, вход требует живого человека]
- Открой в браузере **https://github.com/login/device**
- Введи показанный код (XXXX-XXXX)
- Войди под **GitHub-аккаунтом, который завёл под этого клиента** (не своим личным!), нажми Authorize.
- ВАЖНО: авторизацию нельзя пройти автоматически/токеном — проверено, сервер отдаёт 401.
  Это by design: вход делает человек через браузер. На встрече это делаешь ты.
- После входа туннель привязан к аккаунту и работает.

### Шаг 5. Взять ссылку офиса [док]
После входа туннель даёт постоянную ссылку вида:
```
https://vscode.dev/tunnel/office/<папка>
```
Это и есть «вход в офис с компьютера». Её ты и дашь клиенту.

## ЧАСТЬ 2 — на компьютере клиента [док]

### Самый простой путь — через браузер (ничего не ставить)
1. Дать клиенту ссылку `https://vscode.dev/tunnel/office/...`
2. Клиент открывает её в браузере (Chrome или Edge — в Firefox/Safari часть функций урезана).
3. Первый раз просят войти в тот же аккаунт → входит → видит папки офиса. Работает.

### Путь через программу (если клиент хочет полноценный редактор)
Одинаково на Mac и Windows:
1. Поставить VS Code (code.visualstudio.com), открыть.
2. Поставить расширение **«Remote - Tunnels»** (вкладка Extensions, найти по названию).
3. Нажать **F1** → выбрать строку **«Remote Tunnels: Connect to Tunnel»**.
4. Войти под тем же аккаунтом → откроются папки офиса.

### Перенос файлов ПК ↔ офис [док]
- Затащить документ в офис: перетащить мышью файл в панель файлов слева (в папку knowledge и т.п.).
- Забрать обратно: правый клик по файлу → Download.
- Мелкие правки текста — прямо в редакторе, сохранение (Ctrl/Cmd+S) пишет сразу на сервер.

---

## ГЛАВНОЕ ПРАВИЛО [✓ подтверждено докой]
Компьютер клиента и сервер должны быть под ОДНИМ аккаунтом (GitHub или Microsoft).
→ Под каждого клиента заводим отдельный аккаунт. Под ним ты привязываешь туннель на сервере (Шаг 4),
его же клиент вводит у себя. Отозвать доступ = убрать привязку в настройках аккаунта / снести туннель.

## Убрать туннель (если надо)
```
sudo -u office code tunnel unregister --name office
```

## ЧТО ЕЩЁ ЗАКРЫТЬ ПЕРЕД БОЕМ (открытые хвосты)
- Клиентскую часть (Часть 2) пройти вживую под ОТДЕЛЬНЫМ тестовым GitHub-аккаунтом, сделать скриншоты.
- Решить: встроить Шаги 1-3 в install.sh (автоматом при установке) или ставить туннель отдельным шагом на встрече.
- Проверить, живёт ли туннель после перезагрузки сервера (`code tunnel service install` + linger) — [док, не проверено].
